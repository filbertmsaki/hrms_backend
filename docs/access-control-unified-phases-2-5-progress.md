# Unified access control: phases 2–5 progress

This is a partial implementation. The device detail page has a read-only setup overview showing linked groups, group readiness, included employee counts and last recorded connection health. It requires `attendance_devices:read`, `access_groups:read` and `data_scope:company`. The overview reuses the group preflight and makes no device calls; it does not create drafts, deploy configuration, confirm actual device rights or verify credentials. Group readiness is evaluated for the whole group.

Week-plan and template lists also offer a read-only dependency preview of device, group and recorded employee-right references. It requires `access_schedule_templates:read`, `access_groups:read` and `data_scope:company`. Counts reflect linked HRMS records and do not establish employee employment status or physical device state. A rejected week-plan push no longer advances its last-success timestamp, and the UI reports a rejected push or partial import. Changing a schedule is not yet versioned or automatically deployed.

Attendance employee matching now resolves device-specific assignment/identity mappings before global mappings. Conflicting mappings at the same scope and duplicate HR employee numbers remain unmatched for operator review. Existing raw event history is not changed by this code change; historical events may require an explicitly authorized recalculation after testing. Scheduled policy-based reconciliation now respects an active policy with automatic calculation disabled; incremental punch ingestion and recalculation jobs remain separate paths.

Phases 2–5 are not complete. Shared logical schedule revisions and per-device mappings, impact-aware deployment, persistent setup drafts and orchestration, responsive end-to-end wizard, device read-back, durable access reconciliation, timezone/overnight validation, delayed-event recovery and complete regression/hardware testing remain. Existing device-specific schedules and endpoints remain in place. The Phase 1 overlapping-group safety guard remains active. No migrations or device operations were performed for this progress update.
